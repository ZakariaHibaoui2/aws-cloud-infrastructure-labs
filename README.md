## Architecture

```
                         ┌──────────────────────── Lab VPC 10.0.0.0/16 ────────────────────────┐
  Internet ──► IGW ──►   │  Public 10.0.0.0/24 (AZ-a)          Public 10.0.1.0/24 (AZ-b)         │
                         │   ├─ NAT Gateway                                                     │
                         │   └─ Web tier (Web-SG :80)                                           │
                         │                                                                      │
                         │  Private 10.0.2.0/23 (AZ-a)         Private 10.0.4.0/23 (AZ-b)        │
                         │   ├─ RDS MySQL "inventory-db"  ◄── DB-SG :3306 from Web-SG only      │
                         │   └─ EFS mount target          ◄── NFS :2049 from EFSClient only     │
                         └──────────────────────────────────────────────────────────────────────┘
  S3 bucket (static website endpoint) ──► Café website (public-read bucket policy)
```

## Labs

| # | Lab | What was built | IaC |
|---|---|---|---|
| 1 | **Virtual Private Cloud** | Custom VPC, public/private subnets, Internet Gateway, route tables, NAT | [`01-vpc.yaml`](cloudformation/01-vpc.yaml) |
| 2 | **Amazon RDS** | MySQL `inventory-db` in private subnets, connected to a 2-tier web app | [`02-rds-mysql.yaml`](cloudformation/02-rds-mysql.yaml) |
| 3 | **Amazon EFS** | Encrypted file system, mount targets, least-privilege NFS security groups | [`03-efs.yaml`](cloudformation/03-efs.yaml) |
| 4 | **S3 static website** | Bucket website hosting, public-read bucket policy, café site upload | [`04-s3-static-website.yaml`](cloudformation/04-s3-static-website.yaml) |

## Security practices applied

- **Network isolation**: databases and file systems live only in private subnets; nothing private gets a public IP.
- **Security-group chaining**: RDS accepts 3306 only from `Web-SG`, and EFS accepts 2049 only from `EFSClient` (no CIDR-wide rules).
- **No secrets in code**: the RDS master password is generated by AWS and stored in **Secrets Manager** (`ManageMasterUserPassword`).
- **Encryption at rest** for RDS and EFS; versioning on the website bucket.
- **Snapshot-on-delete** policy on the database.
- **CI**: every push is validated with `cfn-lint` via GitHub Actions.

## Deploy

Requires the [AWS CLI](https://aws.amazon.com/cli/) configured with credentials.

```bash
git clone https://github.com/ZakariaHibaoui2/aws-cloud-infrastructure-labs.git
cd aws-cloud-infrastructure-labs

./scripts/deploy.sh cafe-website-<your-initials>-2026 us-east-1     # VPC → RDS → EFS → S3
./scripts/upload-website.sh cafe-website-<your-initials>-2026 ./site   # folder with index.html, css/, images/
./scripts/teardown.sh cafe-website-<your-initials>-2026              # delete everything (stop charges)
```

> 💸 The NAT Gateway and RDS instance are billable. Run `teardown.sh` when you're done.
